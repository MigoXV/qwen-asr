# 910B 原生独立副本的新旧栈对照

2026-10-16，在不使用容器、不配置vNPU、不改现有运行环境的前提下完成实测。三个路径使用同一份ASR源码 `7409390`、同一模型副本、同一物理Ascend910B4-1和相同服务参数。

**旧栈在独立副本中仍能达到约209倍速的30秒高并发吞吐；Triton路径显著提高单并发，高并发仍略低于旧栈。** 这次排除了ASR源码重构不同和editable入口混用两个因素，比较的是完整软件栈及其版本默认行为，尚不能把差异单独归因于Torch、CANN或vLLM中的一个组件。

后续已继续完成同代码的 CPU/NPU trace、CANN 交叉和图更新调用路径 A/B/A，具体原因与验证结果见[旧软件栈为何更快](ascend-stack-regression-20261016.md)。本页保留第一轮完整 RPC 对照的统计口径。

## 隔离方式与保护边界

证据根目录为 `/home/qwen-asr-isolated/20261016-093250/`，下文简称 `TASK`。没有创建容器、vNPU、虚拟机或设备分区；新旧栈在原生进程中顺序独占物理NPU4，进程内逻辑NPU0，64GiB，驱动26.1.1。

复制Python3.10.22、Poetry、新旧site-packages、editable vLLM源码、两套CANN/ATB及模型到TASK。统一ASR源码来自独立Git克隆。修正仅发生在副本：editable finder、qwen_asr.pth、发行元数据入口和CANN环境脚本中的安装路径。旧环境遗留的 `inferencers.vllm.plugin` 地址在副本中改为当前 `engines.vllm.plugin`；模型和推理算法源码不因此改变。

`run.sh` 以 `env -i` 清空继承环境，再用UID65534和既有设备组GID1000运行；不修改用户组或设备节点权限。该进程对原Python环境、原CANN、驱动安装目录和正式配置没有写权限。HOME、临时目录、vLLM/Triton/Ascend缓存、日志和RPC路径均指向TASK，HF下载关闭，测试端口为50021。

这是软件运行环境隔离，共享宿主内核、系统库、驱动、CPU与物理NPU。没有声称硬件或操作系统绝对隔离，也没有修改锁频、电源策略或NUMA全局配置。正式ASR/LLM一直保持停止，其他服务未改动。

两个独立环境先通过真实NPU张量算子、模型导入、路径和保护权限审计，再通过真实模型RPC冒烟。五次模型进程的 `/proc/maps` 审计未发现加载原Python环境、原CANN或原editable源码的映射；模型和ASR源码副本SHA256与来源一致。记录在 `audit-legacy.json`、`audit-current.json`、`engine-runtimes.jsonl`、`source-sha256.json`、`model-sha256.json`。

全部Python发行包版本和元数据指纹分别在 `runs/legacy/results/package-inventory.json`、`runs/current/results/package-inventory.json`；3128个vLLM/Ascend源码、二进制及测试工具文件的指纹在 `software-and-tools-sha256.json`。完整副本保留在TASK，未重新解析或替换原环境依赖。

版本自带的默认行为并不完全相同：旧栈线程亲和性为0–63核；新栈多数线程为2–61核，ACL/release线程在62/63核。编译pass的版本默认值也有差异，真实配置保存在服务日志。它们属于本轮整体栈对照，不能称为只更换某一个底层库的实验。

## 原环境完整性与复现

对原Python/Poetry、两套CANN/ATB和原editable源码等287745个文件、目录和链接条目进行前后元数据核对，并核对正式配置内容SHA256，变化为0。文件元数据包含类型/权限、大小、mtime/ctime、所有者和符号链接目标，不把读取导致的atime变化作为内容修改。来源模型和ASR源码另作SHA256校验。详见 `protected-before.json`、`protected-after.json`、`protected-changes.json`。

复现前检查物理卡空闲。使用已有独立副本启动，例如：

```bash
TASK=/home/qwen-asr-isolated/20261016-093250
"$TASK/run.sh" legacy python -m qwen_asr.commands.app vllm-ascend \
  --model "$TASK/model" --workers 8 --max-concurrent-rpcs 32 \
  --server-port 50021 --max-model-len 1024 --max-num-batched-tokens 1024 \
  --kv-cache-memory-mib 896 --memory-utilization 0.11 --no-triton-decode
```

在另一个终端运行同副本的benchmark，输出必须换新目录：

```bash
"$TASK/run.sh" legacy python scripts/benchmark_asr.py \
  --workers 8 --server 127.0.0.1:50021 --requests-per-client 1 --min-requests 4 \
  --memory-limit-mib 16384 --output "$TASK/runs/legacy/results/rerun-new"
```

新栈使用 `run.sh current`；优化路径使用 `run.sh optimized` 并将服务参数切为 `--triton-decode`。它们不调用正式服务启动脚本，也不加载正式环境配置。完成后停止自己启动的进程组并确认NPU无进程。`prepare.py`、`run.sh`、`compare.py`、`observe.py`、`frequency.py`、`analyze.py`及完整命令/失败准备记录均保存在TASK；复建应另建任务目录，避免覆盖本轮证据。

各路径完整P50/P95/P99、轮次范围、转写和资源记录位于 `runs/<label>/results/`，汇总为 `results.json`。本轮性能未启用额外profiler；此前的热点和内核验证见[优化报告](ascend-910b-optimization-20261016.md)。最终服务、NPU和端口状态保存在 `final-services.txt`、`final-npu.txt`、`final-ports.txt`；正式ASR/LLM保持inactive，测试进程和50021监听已清理。
