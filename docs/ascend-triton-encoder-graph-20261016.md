# 新软件栈上的 Triton 与音频编码图组合优化

本轮在新软件栈上实现并验证了进一步提速，但收益依赖负载。最终保留 **Triton 解码 + 可选的四档精确长度编码图**；编码图默认关闭。30 秒音频完整 gRPC 的三轮中位数为单并发 **61.330×**、32 并发 **224.827×**，对两次基线中更快的一次分别提升 **3.93% / 10.94%**。5 秒音频相应提升约 17%。10 秒高并发有退化，混合长度的首次捕获也有延迟代价，因此不能宣称全负载提升，也不替用户修改正式服务配置。

原生 FIA 更新优化和 Triton 解码是替代路径，收益不能相加；本轮继续使用 Triton，并针对其剩余热点增加编码图。代码提交 `4b10fd5077bff26bde125ee20ae9d0f3dca0f148`。旧环境不作为交付方案。

参见[根因报告](ascend-stack-regression-20261016.md)、[原生 FIA 对照](ascend-native-fia-update-20261016.md)、[前轮热点](ascend-910b-hotspots-20261016.md)与[完整路线调研和前轮优化](ascend-910b-optimization-20261016.md)。本轮数据、源码哈希与清理记录见[机器可读结果](ascend-triton-encoder-graph-20261016.json)。

## 热点与实测路线

已有 Triton 基线 C32 的 trace 窗口为 5517.24 ms，设备忙碌占比约 0.563。`_partial_gqa` 调用 8736 次，总计 870.59 ms，约占窗口 15.8%；音频编码 Host 包围计时 20 次合计 760.48 ms。后者包含实际设备工作及等待，不是纯 Python 时间；不同嵌套阶段不能相加。既有解码图并未覆盖这段编码器路径。

## 实现边界

只捕获编码器 Transformer 24 层及最终投影，动态卷积、分块与位置准备保留原路径。以实际 token 数、精确累计窗口边界、dtype 和 device 建立图 key；不通过 padding 改变语义。缓存最多 4 个图，观测历史最多 64 项，首次出现的长度先 eager，重复出现才捕获。超过 1024 token 等不符合条件的输入继续 eager。

捕获持有独立输入、CPU 长度张量和输出；重放前复制当前输入，返回独立输出副本，防止上游跨请求缓存被后续重放覆盖。单 Worker 所属线程检查、淘汰前同步和 graph reset 保证资源生命周期。图开关默认关闭，启用需同时开启 Triton，使用受校验的 1.7B BF16 配置。

冷捕获和超过 4 种形状的缓存替换可能增加延迟。混合长度长期测试必须用于判断此代价，不能只用固定长度稳态吞吐决定默认开启。

## 退化排查与采用边界

10秒 C8/C16/C32 相对 A1 分别退化13.38%/4.06%/10.48%，不是单次离群值。直接引擎专项诊断确认：预热后的批次形状会变化，780-token形状在测量阶段首次 eager、随后捕获，捕获约46.46ms。该次直接引擎只用130/780/910三档，零淘汰、无超长回退，因此不能将所有退化归因于缓存淘汰。

C32分段对照中，编码Host累计268.62→69.62ms，模型前向Host却从511.00→710.21ms，stream包围时间1138.20→1322.56ms。编码调用8→12次，prefill批次从每步更多请求变成较小批次：基线出现(8请求,1016tokens)×4，候选出现(8,872)×3及(7,871)×1。已证明批次与前向成本变化；请求到达、异步调度及缓存预算之间的具体因果尚未完全隔离，不将其写成已证实的上游缺陷。

实际RPC专项又确认缓存代价：跨5/10秒及不同并发时，4档缓存记录12次捕获、8次淘汰，部分重新捕获耗时52–68ms。独立扩大为8档后只有9次捕获、1次淘汰，但10秒C8/C16/C32中位数从171.24/185.74/189.22×变为168.23/184.52/188.29×，没有端到端收益；HBM峰值9722→9841MiB。此对照有轻量诊断打印，不能替代上面未插桩矩阵；它足以否定“多缓存就一定更快”。最终不采用8档，不做无证据的调度延迟或容量改动。

混合3轮：C8首字P95 .3814→.4418秒、总延迟P95 .8716→.9249秒；C32首字P95约2.6527秒持平，总延迟P95 3.1149→3.1216秒。低并发混合样本较少，不能推广为准确率或所有线上分布保证。默认保留原Triton路径；固定长度、重复形状负载可以显式开启编码图并按真实业务复测。
